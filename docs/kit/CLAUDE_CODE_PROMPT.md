# 依頼：こつこつ梱包室を実装してください

このフォルダの仕様・JSON・画像・テスト用ZIPを読み、実際に使える日本語Webアプリを実装してください。計画だけで終了せず、機能と検証結果まで仕上げてください。私はPCを持っておらず、iPadで操作します。追加AI API、画像アップロードサーバー、ログインは不要です。最初は静的ホスティング可能なクライアントアプリとして作ってください。既存リポジトリがあればその構成を優先し、なければ小さなTypeScriptプロジェクトにしてください。公開デプロイはこの依頼には含みません。

## 今回の完成範囲
画像・ZIP読込、役割割当、販売前チェック、自作チェックテンプレートの作成・複製・保存・読込、組合せセット、画像差替え、梱包プレビュー、ZIPダウンロードを完成させる。画像編集は別モジュールとして後から追加する。画面上に未実装の編集操作を動くように見せない。編集タブは「準備中」と示し、できることは元画像の書出しと外部で修正した画像の再読込と明示する。デザイン見本の「編集で開く」はこの段階では置き換える。

## 絶対に守ること
- 編集・チェック・梱包は独立。チェックだけ、梱包だけでも開始できる。チェックしていない梱包には「未チェック」と表示する。
- チェックは元画像のバイト、寸法、透明度、DPI、名前を変更しない。ZIP出力時も画像は再エンコードしない。変更は出力コピーのパス・名前だけ。入力ファイルとZIP内ファイルのSHA-256一致を検証する。
- 元ファイルと出力名を分けて管理する。差替え時は安定したassetIdと役割を維持し、検査結果を無効化して再計算。重複ファイル名でも別assetId。
- 外部AIに自動送信しない。端末内処理を実際の通信検証で確認。外部CDN、解析、広告、リモートフォントを使わず、依存資産は同梱する。
- デモ結果を実検査結果として使わない。デモは利用者が選んだときだけ表示し、明示する。
- 公式条件、アプリの推奨、自作ルールを区別。規格チェックは審査合格や著作権の保証ではない。

## 画面とデザイン
assets/design-reference.pngはレイアウト参考。画面画像をそのまま背景に貼るのは禁止。文字・ボタン・カードはHTML/CSSで実装する。見本内のキャラクターや検査数はサンプルであり正解データではない。
背景#F7F4ED、文字#30332F、主色#427E79、白いカード、薄い境界線、控えめな影。警告は琥珀色、読込不能は赤、合格は青緑。色に加え文言とアイコンを使用。
iPad横向き：上に作品名・タブ、中央は可変列のサムネイル一覧、右約320pxの詳細。狭い画面では2列、詳細を下部パネルに。スマホ幅でも横スクロールなし。タッチ領域44px以上、キーボードフォーカス、ラベル、閉じる操作を実装。ドラッグ専用操作を避け、並替えに前へ/後へボタンも設ける。
ヘッダーに「画像を追加」「ZIPを読み込む」を常設。メイン/タブなど必要枠は別欄にし、スタンプ16枚と補助画像2枚を混同しない。空欄の必須枠は「不足1」と表示。
結果は「合格・要確認・エラー・未検査」。画像数とルール違反件数を別表示。一枚に複数の指摘があれば全件表示。理由には実測値、要求値、出典区分を示す。「要確認だけ」で絞込み。
検査前の空状態にmascot-waiting.png、全検査完了かつ指摘ゼロのときだけmascot-checked.png、ZIP生成が成功したときmascot-packed.png。未確認があれば「全部OK」にしない。マスコットは96〜160 CSS pxの補助表示で、画像自体にUI文言を焼き込まない。PNGは透過を維持しobject-fit:contain。

## 入力と検査
MVPは静止PNG/JPEGとZIP。拡張子だけを信用せずシグネチャ・デコードを確認。APNGをacTLチャンクで検出して対象外表示。GIF/SVG/HEIC等は黙って変換せず非対応を伝える。
ファイル単位：寸法（exact/max/none）、形式、ファイル容量、偶数寸法指定、透過、DPI、余白。セット単位：役割ごとの必要枚数と過不足、未割当、出力パス衝突、完成ZIP容量。
透過：alpha<255の有無に加え完全透明画像も区別。透明ピクセルが1つあるだけで「背景処理が正しい」と断言しない。白/黒/市松プレビューを用意。「透明画素あり・見た目の確認は必要」と説明。alpha>8の境界から余白を測り、閾値変更可能なヒューリスティック警告とする。
DPIはPNG pHYs等から取得し、単位なしや情報欠落は「未確認」。72dpi保存の丸め誤差は許容。RGBAがあることをもってRGB規定の完全な証明にしない。未対応メタデータは未確認扱い。
LINE通常静止画テンプレートは同梱JSONを利用。スタンプ数8/16/24/32/40から選択。370×320は最大であり強制一致ではない。補助画像は固定寸法。1MBはアプリでは保守的に1,000,000 bytes、60MBは60,000,000 bytesとしUIで換算方針を明記（公式ページは単位換算を明示していない）。10px程度の余白は目安として警告。DPI未確認も全合格に含めない。
BOOTH用は同梱の「画像素材集・自主ルール」。表紙1200×1200や必要枚数はユーザーの作業用設定でありBOOTH必須条件と表示しない。未確認の販売サイト規則を推測して追加しない。

## テンプレートと自由な組合せ
templates/*.jsonは実装するデータ契約の例。schemaVersionを検査する。未知の版はエラー。標準テンプレートは直接上書きできず複製編集。JSON import/export。役割の追加削除、必要最少/最多数、寸法、形式、容量、透明度条件、出力ディレクトリ・命名をフォームで変更できる。
チェックテンプレートと将来の編集テンプレートは別のデータ型、別の保存領域。チェック側にトリミングや自動リサイズを混ぜない。
「組合せセット」で複数テンプレートをまとめられる。例：商品本体用＋告知カバー用。検査対象は指定した役割の集合のみで、異なるテンプレートが全画像を奪い合わない。一つの元画像を複数の役割参照に利用できる。商品ZIPと宣伝用ZIPを別出力にできる。
結合時の同名roleIdはtemplateIdで名前空間を分ける。同一出力パスは明示的に解決するまで書出しを止める。条件は勝手に緩和しない。役割・枚数・寸法を変えたら影響範囲を再検査。

## 梱包と保存
書出し前にZIP内のツリー、ファイル数、元名→出力名、対象/除外を確認。LINEではルート直下01.png〜NN.png、main.png、tab.pngを出力する。これは本アプリの命名プリセット。余計な説明ファイルを勝手に投稿ZIPへ入れない。
検査エラーのあるセットは通常の投稿用書出しを止める。「作業用として保存」は別操作で、未検査/指摘ありと分かる名前で許可。警告だけの場合は内容を確認して書き出せる。デコード不能・パス衝突は解決必須。
ZIP生成は進捗・中止・失敗時再試行を提供。完成バイト数を測り、上限超過なら投稿用保存を止める。Blob URLは保存操作直後に即revokeせず、Safariの保存処理が使える期間維持。
端末内保存はIndexedDB等。保存失敗を握りつぶさない。テンプレートJSONと、素材・役割・順序・設定を含むプロジェクトバックアップZIPを手動で保存/復元できる。バックアップZIPと投稿ZIPは種類が分かる名称にする。ブラウザ保存は永続保証しないと短く案内。

## 実装上の境界
ZIP読込はファイル数・展開総量・1画像画素数にアプリ上限を設ける（初期値200ファイル/100MB展開/16メガピクセル。販売先の上限とは別）。宣言サイズだけでなく展開中の実バイトも監視、超過は中止。ネストZIPは展開しない。絶対パス、..、重複正規化パスを拒否。暗号化ZIPは非対応。1件失敗しても他の有効画像の確認を継続できる。
巨大画像を一斉Canvas展開せず逐次/小並列で処理し、プレビューを縮小。原本Blobは保持。処理中断、URL/Bitmap解放、破損ZIPからの復帰を実装。
業務判定をUIから分離した純粋関数にして、境界値をテスト。依存パッケージは安定版を調べて固定しlockfileを含める。ブラウザ互換性の不明点は公式資料を確認。

## 受入条件
tests/README.mdのケースを実行する。正常セットの読込→検査→ZIP→再読込で役割数とバイトが維持される。異常セットは説明どおりの指摘が出る。自作テンプレートJSONの再読込と組合せセットも動く。1024×768、768×1024、390px幅を確認。iPad Safari実機で未確認の項目は未確認と報告する。実行したテスト・残っている制限・起動手順をREADMEに書く。ダミー合格、形だけのボタン、実装前の完成宣言は禁止。
